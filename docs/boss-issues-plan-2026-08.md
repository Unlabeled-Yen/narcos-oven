## 1. 【順位 1】#13 六入附醬一律 40ml、90ml = 單買

**老闆語意**：菜單內只要是六入組合附的醬都是 40ml；90ml 是單買品項。

**現況**：`data/menu.yaml` 三個六入 SKU（`:159` 經典六入、`:176` 蘋果六入、`:194` 長型六入）的 contains 都寫 `香料堅果醬90ml`。40ml atom（`:32`、成本 28.96）與其工時/標籤簡稱/產能資料都已存在。90ml 成本 81.91 → 每盒成本高估 $52.95、毛利被低估、工單叫師傅做錯規格。

**規格**：
1. 三行 contains 改 `香料堅果醬40ml`。
2. 全 menu.yaml 掃一遍：任何「組合附醬」一律 40ml、「單品醬」維持 90ml/240ml；六入的 label 簡稱、match_signature 不受影響（signature 不含 ml 數）。
3. **歷史資料遷移**：已入庫訂單的 atoms 是匯入當下展開存進 DB 的，改 menu 不會回溯。寫一次性遷移：凡 items 內含六入組合 SKU 的訂單，其 atoms 中 `香料堅果醬90ml` 改 `香料堅果醬40ml`（僅限來自組合展開的，數量 = 組合數）。遷移前自動觸發備份下載。
4. 驗收：`verify-m4`（分潤成本）重跑、工單頁 atom 統計出現 40ml、遷移前後訂單總數與各 SKU 數守恆。

## 3. 【順位 3】#1 標籤列印預設 = 真實尺寸 4cm×3cm

**老闆語意**：標籤機的標籤紙是 **4cm×3cm 實體尺寸**，列印預設要對準它（推定為熱感應標籤機、一張標籤 = 一頁）。

**現況**：`PrintLabelsPage` 版面寫死 590×315px、一頁 3 張直排、尺寸選項只是文案不驅動版面；`label-renderer.ts`（jsPDF）是無人呼叫的死碼。

**規格**：
1. 列印模式改「**一標一頁**」：`@page { size: 40mm 30mm; margin: 0 }`，每張標籤一個 page-break。
2. 版面以 mm 為單位重排：40×30mm 內放 品項簡稱＋數量＋收件人＋批次/出貨日（依現有 label-data 欄位，內容過長自動縮字）。
3. 螢幕預覽維持清單式（放大顯示），列印 CSS 才切 40×30mm。
4. 預設尺寸 4×3cm；保留尺寸選項但**真的驅動版面**（寬高變數 + @page 同步），舊 60×90 / 75×120 preset 留著。
5. 刪除死碼 `label-renderer.ts`（jsPDF 路線不用；若之後標籤機吃 PDF 再復活）。
6. 驗收：Chrome 列印預覽選 40×30mm 紙、每頁恰一張、無縮放裁切；整批連印 N 張 = N 頁。
7. **標籤機規格（老闆已補、2026-08-06）**：**Xprinter 芯燁 XP-P3301B**
   - 熱感應（無墨、單色）、解析度 **203dpi**、最大列印寬度 72mm、列印速度 70mm/s
   - USB + 藍牙；Windows/Mac 官方驅動、Seagull（BarTender）也有驅動
   - 台灣代理（宜大科技 xprinter.tw）官售 40×30mm 標籤捲 → 4cm×3cm 一標一頁方向確認可行
   - **設計約束（203dpi 單色熱感應）**：40×30mm ≈ 320×240 點，字要大要粗——最小字級 ≥ 8pt 粗體、純黑白、不用灰階/細線/淺色；版面留 1.5-2mm 安全邊（熱感頭邊緣易裁）
   - 列印路徑：瀏覽器 `window.print()` → 系統驅動的 40×30mm 紙張設定；驅動安裝步驟寫進 `docs/`（雇主自行安裝用）

## 3B. 【順位 3B】#15 營養成分表列印（2026-08-06 老闆追加）

**老闆語意**：每盒外面除了出貨標籤，還要貼**盒內每種品項**的營養成分表。例：盒內 肉桂捲×3 + 磅蛋糕×2 + 醬×1 → 貼 **3 張**成分表（每種品項一張、不是每顆一張——以老闆給的例子為準）。系統要像出貨標籤一樣自動計算「這批要印哪幾種、各幾張」。成分表是現成圖檔（5cm×8cm），與印標籤同一頁做成子分頁。

**素材**（`/Users/yen/Downloads/drive-download-20260806T120949Z-1-001/`、日期版本 20260512）：15 張 jpg + 1 個 .ai 原始檔。執行時複製 jpg 進 `src/assets/nutrition/`（檔名正規化為 atom 名）、.ai 原始檔不進 repo（留老闆雲端）。

**Atom ↔ 圖檔對照表**（人工核對過、三類）：

| 狀態 | menu atom → 圖檔 |
|---|---|
| ✅ 直接對上 (7) | 肉桂捲、蘋果肉桂捲、原味巴斯克、芝麻巴斯克、焙茶巴斯克、焙茶栗子巴斯克、香料堅果醬40ml/90ml |
| ⚠️ 名稱近似、需人工確認一次後寫死 (6) | 焦糖蘋果肉桂麵包→「蘋果肉桂麵包」；芝麻焙茶奶酥磅蛋糕→「芝麻焙茶磅蛋糕」；鳳梨肉桂奶酥磅蛋糕→「鳳梨肉桂磅蛋糕」；白玉原味巴斯克→「原味白玉巴斯克」；白玉芝麻巴斯克→「芝麻白玉巴斯克」；白玉烏龍茶巴斯克→「白玉烏龍巴斯克」 |
| ✅ 已解（8/6 Yen 核） | 香料堅果醬240ml → 圖檔「4.250ml」：**檔名誤植**，圖片內文寫 240ml、與菜單一致，照常對應（匯入資產時檔名正規化）；瑕疵小脆捲10顆、無麩烤餅 → **免貼**（`nutrition_label: none`） |

**規格**：
1. `menu.yaml` 每個 atom 加選填欄 `nutrition_label: <檔名>`；`MenuSchema` 同步加欄。**對照關係只存在這裡**（單一事實來源），程式不做任何模糊比對/自動猜檔名——名稱近似的 6 筆由人確認後寫死。
2. 免貼清單顯式化：不需要成分表的 atom 標 `nutrition_label: none`（明寫），**留空 = 未決 = 匯出時 loud 警告**。空值與 none 語意分開，杜絕「忘了設定」與「確認免貼」混淆。
3. **盒模型（2026-08-06 Yen 定案：盒內容不用猜、由資料確定）**：
   - **組合品項**：每 1 單位 = 1 盒、盒內容 = menu.yaml 的 contains。經典六入×2 = 2 盒 → 每盒貼「肉桂捲+40ml醬」各 1 張、共 4 張。
   - **散裝單品**：同一張訂單的散裝單品預設併成 1 盒、盒內每種各 1 張。
   - **客製單**：盒內容由老闆組單時親手標示（見 #2 的分盒設計）、精確計算。
   - **守恆檢查**：系統推導盒數 vs 訂單「標籤張數」欄位比對，不一致 → loud 警示該單「推導 N 盒、標籤張數 M，請人工核對成分表配置」。一致才靜靜通過。**取代原「寧多印×盒數」預設——已不需要。**
4. 計數純函式 `nutritionSheetsFor(orders)`：逐單展開為盒 → 每盒取相異品項各 1 張；輸出 `{ atom, 張數, 來源訂單清單 }[]` 供整批加總與溯源。
5. UI：印標籤頁（`print-labels`）加子分頁「營養成分表」，共用同一個批次選擇器；畫面列「本批需求總表」（品項 × 張數 × 縮圖）+ 列印鈕。
6. 列印：與 #1 同一套 `labelLayout` 基建、新 preset `5x8cm` → `@page size: 50mm 80mm`、一張一頁、圖檔等比滿版（50mm ≤ XP-P3301B 最大列印寬 72mm，可印）。
7. 版本管理:資產檔名保留 `20260512` 日期前綴，頁面顯示「成分表版本 2026-05-12」；老闆換新版圖 → 覆蓋檔案 + 改版本字串。

## 5. 【順位 5】#12 指定日吃 html、可呈現可紀錄

**老闆語意**：賣貨便的「指定出貨日」只有 html（網頁存檔）才有，請加入 html 解析讓指定日被呈現與紀錄。

## 6. 【順位 6】#7 駐店運費可計算、可呈現

**老闆語意**：駐店運費老闆自己出，系統要算得出來、也要說明呈現。

**現況**：駐店對帳頁算對（實收 = 總額 − 運費），但 `compute-payout.ts` 的物流成本只認賣貨便/宅配/面交/KOL，駐店 = 0 成本 → 分潤統計淨利被高估（高估額 = 老闆自掏運費）。

**規格**：
1. `compute-payout.ts` `logisticsCostFor` 加駐店分支：`channel === "駐店"` → 成本 = 該單 `freight_cost`（無值 = 0）。
2. 分潤統計頁與儀表板的成本拆解各加一列「駐店運費（老闆自付）」，與包材/物流並列，讓「這筆錢從毛利被扣掉」看得見。
3. `compute-dashboard.ts` / `compute-stats.ts` 同步檢查駐店通路的成本口徑一致。
4. 驗收：造一筆駐店單（總額 1000、運費 120）→ 分潤頁淨利含 −120、成本拆解出現該列；駐店對帳頁數字不變。

## 7. 【順位 7】#6 期間統計一律用「出貨日」

**老闆語意**：系統一律使用出貨日。（「不完全一致」的意思見下）

**現況（= 我說的不一致）**：各頁篩「期間」時用的日期欄不同 —
- 工單/出貨明細/印標籤：`shippingDayFor(batchDate)` = 出貨日 ✅
- 駐店對帳頁：`batchDate ?? order_date`（出爐日、缺值退訂購日）
- 分潤/儀表板期間篩選：以 batchDate（出爐日）為主
同一張單可能出爐 7/30、出貨 8/1 → 月報表歸 7 月還是 8 月，各頁答案不同。

**規格**：
1. `src/domain` 新增單一函式 `effectiveShipDate(order)`：賣貨便/宅配/面交/KOL → `shippingDayFor(batchDate)`；駐店 → `batchDate`（駐店的 batchDate 本身就是到貨=出貨日）；無 batchDate → null（列「未排」，不落任何期間）。
2. 所有期間篩選（分潤、出爐統計、儀表板、駐店對帳、期間摘要 Excel）一律改走這個函式。
3. 驗收：跨月案例（出爐 7/31、出貨 8/1）在每一頁都歸 8 月；各頁月合計互相對得上。

## 9. 【順位 9】#11 + #14 批次跨頁雙向連動

**老闆語意（#14）**:排程頁停在某批次 → 點到工單或出貨明細就是該批次，不用再找；反向亦然（雙向連動）。#11：工單批次不用「下週下週」慢慢按。

**現況**：四頁各自 useState 記批次、切頁即忘、預設規則三套；工單被「週」座標綁死，出貨明細/印標籤已是跨週批次清單。

**規格**：
1. 新增全域「當前批次」狀態：hash query `#/worksheet?batch=2026-08-12`，由 `AppShell` 統一讀寫（重新整理也保留）。

## 10. 【順位 10】#8 訂單可編輯架構

**老闆語意**：資料要長期累積做月/季/年統計，所以不是清掉，而是**可編輯**——例如不小心重複匯入同批資料，要能調整。

**規格**：
1. **單筆編輯**：訂單總覽每列鎖頭解鎖後除狀態外，開放編輯：出貨批次、收件資訊、品項數量、金額欄。每次編輯寫入既有 `order_changes`（來源標 `manual_edit`），守恆 banner 照常公告「手動修改 N 筆」。
2. **單筆刪除（軟刪）**：不物理刪除；status 加 `voided`（作廢），預設所有統計/排程/工單排除、訂單總覽可篩「已作廢」復原。守恆律：作廢/復原都進 `order_changes`，總數公告「N 筆作廢中」。
3. **重複偵測工具**：訂單總覽加「找重複」按鈕 → 列出可疑組（同通路 + 同訂單編號、或面交/手打的同 content hash + 同日）→ 每組並排顯示、勾選要作廢的那筆 → 批次作廢。不自動刪、一律人拍板。
4. **防呆在源頭**：匯入時若整批訂單編號與既有 DB 100% 重疊且無任何 diff → 提示「這批已匯入過、本次無變化」，不重複寫入。
5. 驗收：重複拖同一份 xlsx 兩次 → 匯入提示攔截；手動改數量 → 統計同步變 + change log 有紀錄；作廢單不進任何統計但可復原。

## 11. 【順位 11】#2 客製化商品（手打單自由組合）

**老闆語意**：客製化 = 走手打單，給老闆極大彈性自行組合商品，系統要把**單品列成選項**，組出來的單能進排程。

**規格**：

2b. **以盒為單位組單（2026-08-06 定案、服務 #15 成分表）**：UI 結構是「第 1 盒：〔品項×數量 列表〕→ ＋新增一盒」；老闆組單的動作本身就是標示每盒內容。出貨標籤張數自動 = 盒數（不手填）；成分表逐盒精確計算。資料面：OrderItem 加選填欄 `box_no`（第幾盒），一般單不使用此欄。

### 驗證總則（適用每一項）

1. **只測真程式碼**：所有新驗證放 `tests/*.test.ts`，用 `node --test` 直接 import `src/` 真模組（跟現有 `compute-dashboard.window.test.ts` 同一套路）。**禁止**像舊 verify-m1 那樣在腳本裡內嵌複製版邏輯——複製版會跟真程式漂移，測到的不是上線的碼。只有需要「拖真實 xlsx/html 跑完整 parser」的端到端檢查才另立 `scripts/verify-*.mjs`，且一樣 import 真模組。

- 每完成一項：`pnpm build` + `pnpm test`（含該項新測試）+ 黃金值比對 + 手動驗收條款，全過才 commit。
