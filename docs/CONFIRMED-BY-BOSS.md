## 1. c22（配送數量）= 2 → 出幾張標籤？

**答**：**每箱一張標籤**。

**Pipeline 影響**：
- Stage 5 (Recipient Grouping) 產出的 `labelCount` 直接 = c22
- 標籤編號規則：一單 c22=2 → 「2-1」「2-2」；c22=3 → 「3-1」「3-2」「3-3」
- 面交/KOL 沒有 c22 概念，用**同批次同收件人的品項數** = 標籤數

## 3. 未付款訂單（c5 = 「訂單成立（尚未付款）」）是否進本批出爐量？

**答**：**未付款不納入出爐量，付款確認才排程**。

**Pipeline 影響**：
- **Stage 1 (Parse) 新增 filter**：`c5 !== "付款完成..."` → 進 `pending_payment` 桶，**不進主軌**
- 儀表板要有「等待付款訂單」列表，數字獨立顯示（雇主可追進度）
- 客人一旦付款、後端有機制標記 `paid: true` → 該筆重跑 pipeline 進出爐排程

**待補問**：雇主怎麼標記「已付款」？（賣貨便匯出的隔天就會自動更新 c5、還是要雇主手動改？）

## 4. 客人備註（c28）藏日期指示 vs c12 選項不一致

**答**：**客人備註是重要的、但出爐排程需要後續經 AI 設計流程、要再討論**。

**Pipeline 影響（v1 保守做法）**：
- Stage 4 (Batch Assignment) 檢查 c28 是否 regex 中日期樣式
- 若 c28 含日期且 c12 也有指定出貨日、且**兩者不同** → 進 `pending_conflict_date` 桶（新 code），標「c12 選 X、c28 寫 Y」
- 若 c28 含日期但 c12 沒選 → 進 `pending_batch_date`，AI 建議用 c28 日期、Yen 拍板
- v2 目標：AI 幫排程（雇主要與 Yen 再討論怎麼設計）

## 5. 賣貨便 c17 運費（買家付的）是否算 NARCOS 營收？

**答**：**錢到店家、店家再付給物流**——**運費算營收**，但需另扣「實際物流成本」算淨營收。

**Pipeline 影響**：
- 總營收 = c21 (含運費) ✅
- 淨營收 = c21 - 品項成本 - 包材 - **實際物流費**
- menu.yaml 或 config 加一格：**物流成本表**（超商取貨 $60、宅配 $130 等實際店家付出金額）
- v1 用「每單物流估 $100」預設，雇主之後補精確金額

## 6. KOL 未完成 sheet 進度狀態機

**答**：**已寄出 (c6 = True) 就判定為已完成**。

**Pipeline 影響**：
- KOL parser 讀「未完成」sheet 時，`c6 === True` → **視為完成，不進本批出爐量**（等同「已完成」sheet 語意）
- `c6 === False` + `c4 (寄貨時間) === 本批日期` → 進本批出爐量
- `c6 === False` + `c4` 是模糊字串（如「七月台中面交」）→ 進 `pending_batch_date`
- **不再看** c0 (折扣碼設置完成) 欄——那是 Yen 內部管理欄，不影響出爐

## 10. `長型4入_兩磅` SKU 的 display_name 尾巴被 Excel 截斷

**答**：**權威原文只需要符合中文字**。

**這是最大架構影響**——原本以為 display_name 要跟賣貨便 c12 百分百一致（含 `✦` `✧` 空白），現在改為：

**新 lookup 演算法**：
1. **先跟 `aliases[]` 做 exact 字串 match**（100% 命中最快最準）
2. 若無命中，跟 `match_signature` 做**中文字子串 include/exclude 判定**
3. `display_name` 純粹是 UI 顯示用（中文精簡版）

**menu.yaml schema 新增**：
```yaml
match_signature:
  include: [中文字1, 中文字2, ...]   # 全部必包含
  exclude: [中文字3, ...]            # 全部不能包含
```

例：
- `原味巴斯克`: `include: [原味巴斯克], exclude: [白玉, 焙茶, 芝麻]`
- `白玉原味巴斯克`: `include: [白玉, 原味巴斯克]`
